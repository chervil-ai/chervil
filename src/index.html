Chat

“Just a chatbot” mode (the 💬 button) answers in the conversation instead of composing a page. Replies stream in as Sprig writes them.

Chat is a conversation you're waiting on, so a quicker model usually wins. It matters most on a reasoning model, which thinks before it writes a single word — picking a non-reasoning variant here can be the difference between waiting three seconds and half a second. Your main model is untouched: composed pages, Deep Dive and skills all still use it.

Search

Chervil answers with Sprig by default. To do a plain web search instead, start the address bar with a bang: g! Google, ddg! DuckDuckGo, b! Bing, or s! for your default above — e.g. g! best hiking boots.

Provider & model — bring your own API

Switch providers to save money, work offline, or use a model you prefer. Each has trade-offs — pick what fits the task. Claude, Grok, Gemini, and OpenAI do live web grounding (real, cited sources); Azure and Ollama compose from the model's own knowledge. Claude also offers the full two-phase Deep Dive.

Why optional? Ollama running on your own machine needs no key — leave this blank. Add a token only if you point the server URL below at a remote or password-protected Ollama (behind a reverse proxy, or Ollama's cloud). When set, it's sent as an Authorization: Bearer header.

Audio narration (text-to-speech)

Used by the 🔊 Audio button on composed pages. Voices come from your operating system — look for ones labelled "Natural" or "Online" for the best quality.

Voice input (speech-to-text)

Talk to Sprig with the 🎤 button in the chat box. Recordings are sent to a Whisper-compatible transcription service of your choice (OpenAI, Groq, Azure, or a local whisper server) — Claude can't transcribe audio, so this uses its own key. The audio is sent only to this endpoint, never stored.

Publishing (Chervil Pro)

Publish a lesson, quiz, or any interactive page (clock, calculator, converter…) to a shareable getchervil.com link. Sign in at getchervil.com/me, generate a publish token, and paste it here. Then use 🌐 Publish to web from any page's Export menu. (Pages that call Sprig at runtime won't be interactive when hosted.)

Blogs (WordPress, Substack & Medium)

Publish a Chervil page straight to your blog. Use “Publish to web → To WordPress / Substack / Medium…” on any page. WordPress posts a real draft via its API; Substack/Medium open pre-filled — you always review and hit Publish. WordPress app passwords are kept in your encrypted vault, never here.

Sync between computers

Point Chervil's data (tabs, history, Spaces, agents) at a folder your cloud client already syncs — inside OneDrive, Google Drive, or Dropbox. Set the same folder on each computer and your sessions follow you. Note: API keys aren't synced (they're encrypted per-machine — re-enter once per computer), and running Chervil on two machines at once is last-writer-wins. Using OneDrive? In File Explorer, right-click your sync folder → Always keep on this device — otherwise OneDrive offloads the files and re-downloads them as you use Chervil (the "Automatic file downloads" popup). Google Drive/Dropbox have the same "available offline" option.

Your Web — search what you’ve read

Chervil already keeps the pages it composes for you, so you can search them in the Library. It can also keep the text of the websites you read — then you can ask Sprig things like “what was that laptop review I read last month?” and get an answer from your own reading, instantly and for free.

This is local and private. The index is a file on this computer, it is never synced and never uploaded, and no AI ever sees a page just because you read it — the text only reaches your AI provider if you ask a question it answers, exactly like attaching a file. It’s off unless you turn it on.

Noticing what you’re researching

When you read around the same subject across a few different sites, Chervil can offer to pull it all together into one page — what you found, where your sources disagree, and what you haven’t looked at yet.

Noticing is free and local (no AI is involved in spotting the topic). Sprig never writes the page on its own — you get a quiet card offering it, and nothing is composed, and nothing is spent, until you click it. Needs “keep the text of websites I read” above.

Offer after How much reading on one subject before Chervil offers. Higher = only when you’ve really been digging — raise this if it offers things you didn’t care about. Lower = offers sooner. It always needs at least two different websites, so reading one site a lot never counts as researching a subject.

Listening — “Hey Sprig”

Let Chervil listen for a wake word and pop the Quick-Ask bar so you can speak a request hands-free. Detection runs fully on-device and free (openWakeWord, no account or key) — your mic audio never leaves the machine until you actually speak a command, which is then transcribed by your configured voice-input service above.

Wake word Built-in words work immediately. For the literal “Hey Sprig”, train a free openWakeWord model (a single-command trainer or the openWakeWord Colab) and load the resulting .onnx here.
Wake-word threshold How clear a match Chervil needs before it wakes. Higher = fewer accidental triggers — raise this if background noise or a TV keeps setting it off. Lower = easier to trigger.

MCP servers Claude only

Connect remote Model Context Protocol servers to give Sprig extra tools and data (e.g. your calendar, a database, a SaaS app). Sprig can call their tools while composing a page. Their tools run on Anthropic's side as part of the request — so only add servers you trust, and prefer read-only ones. Works with the Claude provider only; other providers ignore these.

Remote URL servers only (SSE/HTTP). Local/stdio servers aren't supported yet. The token is stored on this machine and sent to Anthropic as the server's authorization.

Images

Claude can't generate images, so Chervil uses your OpenAI, Google Gemini, or Grok (xAI) key to make a hero image. Off by default — image generation costs money (billed to your own key). One image per composed page.

Passwords encrypted

Save logins for real sites and fill them back in with the 🔑 button. Passwords are encrypted with a master passphrase (and your OS keychain) and never shown to Sprig, never sent anywhere. Sprig itself never types passwords. The vault auto-locks (see below) and asks for your passphrase again before filling. (Windows Hello unlock is planned.)

Payment cards encrypted

Save cards to fill at checkout with the 💳 button. Cards live in the same encrypted vault as your passwords (one master passphrase) and are never shown to Sprig, never sent anywhere. For your security, the CVC/security code is never stored — you type it yourself at checkout. Chervil never auto-submits a payment.

What you’ve corrected

When Sprig gets something wrong, type /correct followed by what’s actually true — “/correct our office moved to Dayton in March”. Sprig applies it to every page it composes from then on, so it stops making the same mistake. These live on this computer with the rest of your settings.

Each one is dated, and a correction loses to a fresher live source: if Sprig finds today that a price or a role has changed, it goes with what it found and tells you, so an old note can’t quietly outlive the truth.

Autofill

Save your details to fill forms on real sites — on a website, just say “fill the form.” Passwords and card details are never stored or auto-filled.

Your places

Register your personal corners of the web — then say “open my email” (typed, omnibox, or “Hey Sprig”), get one-click shortcuts on the welcome screen, have mailto: links open your webmail, and share what you publish to your networks. URLs only — logins stay in the password vault.

About you (personal memory)

Tell Sprig about yourself — location, interests, work, preferences, how you like answers. Sprig uses this to tailor every page it composes (kept on this machine, sent only to your chosen model).
